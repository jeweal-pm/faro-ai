# Prompt-driven document revisions

- Audited existing PDF/DOCX/XLSX export and found it only supports rectangular PO tables; PDF alone has an orientation field.
- Verified the two latest generated PDFs are physically portrait (A3, 842×1191 pt). Identical `Download PDF` labels make old and new versions easy to confuse.
- Added ADR-0047 and the implementation spec for typed document revisions, versioned download labels, formatting and uploaded images.
- Implemented bounded prompt-driven revisions of FaroAI-generated PDF, DOCX and XLSX in the active PO chat: paper orientation and size, typography sizes, text alignment and colors, title/subtitle/footer, page numbers, margins, table columns, and an attached PNG/JPEG image with position and width.
- Jev chooses the eligible task model for open-ended document instructions. The model returns a typed patch; the gateway and worker validate before generating a new version. Explicit orientation requests, including the common `portarit` typo, use the direct path.
- Rebuilt and restarted `ai-service`, `api`, `backoffice`, and the separate `artifact-worker`. The API and Backoffice responded with HTTP 200. The live planner returned the requested larger centered title and page numbers. A live artifact job produced a downloadable A4 portrait PDF with the requested hidden column and footer.
- Gateway targeted tests: 2 passed. Built artifact-worker tests: 6 passed. Docker production build and TypeScript check passed. No dangling images remained after rebuilding.
- Scope follows the user's clarification: documents FaroAI generated in the active chat. Editing externally uploaded files and arbitrary pixel-level PDF editing are not part of this implementation.
- Follow-up fix: split document colors into body text, title, table-header text, and table-header background values. The previous single `accent_color` did not distinguish header text from fill, and DOCX did not apply header fill. All three renderers now apply explicit header colors; `accent_color` remains a backward-compatible background alias.
- Updated the planner prompt with Thai and English color semantics, added validated color controls across PDF, DOCX, and XLSX, and released Base Skills as `2026.11.05.2` (PDF/DOCX/XLSX `1.2.0`). Rebuilt/restarted the four affected containers; API and frontend return HTTP 200 and the skill registry loads all three updated versions.
- Diagnosed “FaroAI could not interpret the document change”: OpenRouter returned HTTP 200 with malformed/non-JSON model content (`JSONDecodeError`). Added JSON mode with compatibility retry and balanced JSON-object extraction. Rebuilt/restarted `ai-service`; the same prompt now returns HTTP 200 with `text_color: #333333`, `title_color: #000080`, and `header_background_color: #FFD700`.
