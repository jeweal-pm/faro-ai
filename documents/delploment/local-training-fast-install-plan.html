เตรียมเครื่องฝึก LoRA แยกจาก FAROAI ให้พร้อมใช้งานเร็ว เก็บ dependencies, model cache และไฟล์งานข้ามการปิดเครื่อง พร้อมควบคุมค่า GPU เมื่อไม่ได้เทรน

แนวทางหลักที่เสนอ: AWS EC2 On-Demand + encrypted EBS. Stop EC2 เมื่อไม่ใช้เพื่อลดค่า compute; EBS ยังเก็บข้อมูลแต่คิดค่าพื้นที่ต่อ. สำหรับ runner ตอนนี้เริ่มพิจารณา g4dn.xlarge ที่มี T4 VRAM 16 GB. ราคาในเอกสารราว $0.526/ชั่วโมงใน us-east-1 เป็น snapshot จากผู้ให้บริการข้อมูลราคา ต้องยืนยันใน AWS console ก่อนสร้างเครื่อง.

1. เป้าหมายการใช้งาน

เตรียม environment ให้เสร็จครั้งเดียว รอบถัดไปให้ทำตามขั้นตอนสั้นๆ นี้:

  1. เปิด GPU instance จาก image ที่เตรียมไว้
  2. ตรวจ CUDA และ mount volume สำหรับงาน
  3. นำ dataset ที่ผ่าน consent/review เข้าพื้นที่ฝึก
  4. สั่ง runner โดยใช้ model cache ที่มีอยู่แล้ว
  5. ตรวจผลลัพธ์และหยุด GPU instance
เป้าหมายด้านความเร็ว: รอบถัดไปไม่ติดตั้ง Python dependencies หรือดาวน์โหลด base model ซ้ำ ต้องวัดเวลาจริงกับ cloud และ region ที่เลือกก่อนถือว่าผ่าน

2. เลือกผู้ให้บริการ

ผู้ให้บริการวิธีเปิด/ปิดผลกับค่าใช้จ่ายเหมาะกับกรณี
AWS EC2 + EBSแนวทางหลักStop/Start instance และคง EBS ไว้หยุดค่า compute เมื่อ Stop; EBS/snapshot ยังมี storage chargeใช้งานซ้ำและอยากเก็บ OS/environment เดิมไว้
Google Cloud VM + Persistent DiskStop/Start VM และคง Persistent Disk ไว้หยุด CPU/GPU; disk/IP ที่เก็บไว้ยังคิดเงิน. ตรวจ GPU capacity ใน zoneทีมที่ใช้งาน Google Cloud อยู่แล้ว
DigitalOcean GPU DropletDestroy Droplet แล้วสร้างใหม่เมื่อต้องใช้Power off ยังคิดค่า GPU จนกว่าจะ Destroy; volume แยกคิดเงินงานเป็นครั้งคราวและรับ setup/rebuild เครื่องใหม่ได้
Runpod Podสร้าง Pod ตามรอบงานตรวจ Cloud tier, region และ storage charge ก่อน Deploy; อย่าคิดว่าราคา Pod รวม storage ที่เก็บข้ามรอบต้องการเช่าเครื่อง GPU ตามรอบและเช็กยอดก่อนสร้างทุกครั้ง

ข้อเสนอเริ่มต้น: ใช้ AWS EC2 + EBS สำหรับ setup นี้ เพราะ Stop/Start ได้และเก็บ environment บนเครื่องได้. ราคากับ availability เปลี่ยนตาม region, OS และ quota จึงต้องยืนยันก่อนเปิดจริง.

3. โครงสร้างพื้นที่เก็บข้อมูล

แยกข้อมูลที่ต้องเก็บจาก scratch/temporary storage. ตัวอย่าง volume ที่ mount คงที่ไว้ที่ /mnt/faro-training:

/mnt/faro-training/
├── datasets/             # JSONL export ที่อนุมัติแล้ว; จำกัดสิทธิ์และเข้ารหัส
├── model-cache/          # Transformers checkpoint ที่ดาวน์โหลดครั้งแรก
├── runs/<run-id>/        # adapter, tokenizer metadata, training-manifest.json
├── logs/                 # log แต่ละรอบ; ห้ามใส่ secret
└── backups/              # ที่พักชั่วคราวก่อนส่งกลับ storage ปลายทาง
  • เก็บ OS, Python, dependencies และ runner ใน boot disk/image ที่สร้างซ้ำได้.
  • เก็บ dataset, model cache และผลลัพธ์บน encrypted persistent volume หรือ storage ที่ mount กลับ path เดิมได้.
  • แยกแต่ละรอบด้วย runs/<run-id> เพื่อไม่เขียน adapter ทับงานเดิม.
  • ห้ามเก็บข้อมูลสำคัญไว้บน instance-store/local scratch เพียงที่เดียว เพราะอาจหายเมื่อหยุดหรือสร้าง instance ใหม่.
  • กำหนด retention และลบ dataset/cache ที่ไม่ต้องเก็บ; volume ยังคงคิดค่า storage แม้ GPU หยุด.

4. เตรียม environment ครั้งแรก

  1. เลือก Cloud และสิทธิ์: ใช้บัญชีทดลองเฉพาะ, ตั้ง budget alert, ตรวจ GPU quota/region/ราคา Linux/disk/IP/network. ใช้ IAM role ที่ให้สิทธิ์เท่าที่จำเป็น.
  2. สร้างเครื่องส่วนตัว: ใช้ Linux x86_64 image ที่รองรับ NVIDIA CUDA; พิจารณา AWS Deep Learning AMI หรือ base image ที่ทีมดูแลได้. ห้ามเปิด SSH/RDP สู่ internet แบบกว้าง; ใช้ Session Manager หรือ allowlist IP ชั่วคราว.
  3. เข้ารหัสดิสก์: เข้ารหัส boot disk, data disk และ snapshot; ปิด public access ของ object storage.
  4. ติดตั้ง software: ใช้ Python 3.12 และ virtual environment; ติดตั้ง runner/dependencies ด้วย pip --no-cache-dir. Pin เวอร์ชันที่ทดสอบแล้วใน lock file เพราะ requirements ปัจจุบันเป็น version ranges.
  5. ตรวจ GPU: ตรวจ nvidia-smi และ torch.cuda.is_available() ว่า driver/CUDA/PyTorch เห็น GPU จริง.
  6. เตรียม volume: mount encrypted data volume ที่ /mnt/faro-training; ตรวจ filesystem, permissions, พื้นที่ว่าง และเจ้าของ directory.
  7. Warm model cache: ดาวน์โหลดเฉพาะ Transformers checkpoint ที่เลือกและมี license อนุญาตลง model-cache. ตั้ง path คงที่และไม่ใส่ API key ใน shell history/config.
  8. สร้าง image ที่ใช้ซ้ำ: รัน smoke check ขนาดเล็กให้ผ่าน แล้วสร้าง AMI/snapshot ของ boot environment. ห้าม bake dataset หรือ credentials ลง image.
  9. บันทึกเวอร์ชัน: จด Python, driver, CUDA, PyTorch/Transformers/PEFT, image ID, รุ่น GPU, region และวันที่ไว้ใน runbook.

5. วิธีใช้ซ้ำในแต่ละรอบ

ก่อนเปิด GPU

  • ยืนยันเงื่อนไข local training ตาม ADR-0012/ADR-0022/ADR-0023: เปิด local LLM, มี tenant authorization และ consent ตามแหล่งข้อมูล, ผ่าน human review และอนุมัติ preferred answer แล้ว; รองรับ hosted multi-tenant โดย export แยก tenant.
  • Export dataset ผ่าน Backoffice เก็บชั่วคราวบนพื้นที่เข้ารหัส และตรวจ manifest/hash กับ tenant scope.
  • ยืนยันว่าไม่ใช่ shared-training data และไม่มี secret/ข้อมูลที่ไม่ควรนำไปฝึก.
  • กำหนด run-id, ระยะเวลา และ budget alert ก่อนเริ่ม.

เปิดเครื่องและเทรน

  1. Start instance จาก image ที่เตรียมไว้.
  2. Mount persistent volume แล้วตรวจ nvidia-smi, CUDA, free disk และ model cache.
  3. วาง dataset ที่อนุมัติแล้วใน datasets/<run-id>.jsonl และตรวจ hash.
  4. รันคำสั่งนี้โดยใช้ output แยกตามรอบ:
python train_lora.py \
  --dataset /mnt/faro-training/datasets/<run-id>.jsonl \
  --model Qwen/Qwen2.5-0.5B-Instruct \
  --model-cache-dir /mnt/faro-training/model-cache \
  --output-dir /mnt/faro-training/runs/<run-id> \
  --max-sequence-length 512
  1. เก็บ log และตรวจว่ามี adapter/, tokenizer metadata และ training-manifest.json. ประเมินกับ held-out prompts ก่อนนำไปใช้.
  2. สำรองผลที่ต้องเก็บกลับ encrypted S3/object storage หรือดาวน์โหลดสู่พื้นที่ควบคุมของ tenant. ห้ามปล่อย adapter เข้า LM Studio/production อัตโนมัติ.
  3. ตรวจสำเนาให้ครบแล้ว Stop instance; ลบข้อมูลชั่วคราวตาม retention policy.

6. ค่าใช้จ่ายและการปิดเครื่อง

ผู้ให้บริการเมื่อต้องหยุดชั่วคราวสิ่งที่ยังคิดเงิน/ต้องระวัง
AWSStop EC2EBS/snapshot ยังคิด storage. อย่า Terminate จนตรวจ DeleteOnTermination และ backup แล้ว.
Google CloudStop VMPersistent disk/IP ที่เก็บไว้ยังคิดค่าใช้จ่าย; Local SSD อาจไม่คงข้อมูล.
DigitalOcean GPUสำรองข้อมูลแล้ว DestroyPower off ยังคิดค่า GPU; backup boot disk ก่อน Destroy.
ทุกค่ายตรวจ billing console หลัง stop/destroyลบ unattached volumes, snapshots, public IP และ storage ที่ไม่ต้องใช้. ตั้ง lifecycle expiration ให้ object storage.

เก็บ artifact บน object storage มี storage/egress charge. ต้องกำหนด encryption, access policy, lifecycle expiration และ audit ให้ครบ.

7. Security และการจัดการข้อมูล

  • Cloud GPU เป็นเครื่องฝึกแยกจาก FaroAI; ไม่เปิด inbound API และไม่ให้ runner ต่อ Qdrant, FaroAI database, OpenRouter หรือ LM Studio API.
  • ใช้เฉพาะ JSONL export ที่ผ่าน consent/review; จำกัดข้อมูลต่อ tenant และสิทธิ์ผู้ปฏิบัติงาน.
  • เข้ารหัสดิสก์, volume, snapshots, object storage และทางส่งข้อมูล; ใช้ role/short-lived credentials แทน key ที่ฝังใน image.
  • ห้ามใส่ข้อมูลจริงใน image/AMI, repository, issue หรือ log; ห้ามเปิด volume เป็น public.
  • ตรวจ model license, provenance, dataset hash และ output hash ก่อนส่งต่อ.
  • ลบ dataset, checkpoint, cache และสำเนา backup ตาม retention policy ของ tenant เมื่อหมดความจำเป็น.
  • Qdrant ใช้เป็น retrieval index เท่านั้น. Dataset และ adapter ไม่ถูกส่งเข้า Qdrant.

8. ข้อจำกัดของ runner ปัจจุบัน

ถ้าเครื่องหยุดกลางงาน เทรนต่อจากจุดเดิมไม่ได้ในตอนนี้
Runner ตั้ง save_strategy="epoch", ค่าเริ่มต้น 1 epoch และไม่มี --resume-from-checkpoint. ถ้าถูกหยุดกลาง epoch ต้องเริ่มรอบใหม่. ควรรอ Trainer จบและตรวจ output ก่อนหยุด instance.

หากต้องรองรับ interruption/resume ภายหลัง ให้ทำ enhancement แยก: periodic checkpoint, resume argument, manifest สถานะ และทดสอบ restore; อัปเดต SPEC/changelog ก่อนใช้จริง. ไม่ย้าย training dependencies เข้า FaroAI Docker image และไม่เริ่มเทรนอัตโนมัติหลัง export.

9. Checklist รับมอบเมื่อลงมือทำ

  • เปิด/หยุด GPU ได้จาก console หรือ script จำกัดสิทธิ์ และค่า compute ลด/หยุดตาม billing page.
  • Boot image มี Python, runner dependencies และ NVIDIA runtime ที่ตรวจเวอร์ชันได้.
  • หลัง Stop/Start, persistent volume กลับ path เดิมและ model cache ใช้ซ้ำได้โดยไม่โหลด base model ใหม่.
  • dataset/output ไม่อยู่บน temporary disk เพียงที่เดียว; เข้ารหัสและจำกัดสิทธิ์.
  • run log เก็บ run-id, dataset hash, model ID, image/GPU, parameters สำคัญ, เวลาเริ่ม/จบ และ output location โดยไม่มี secret.
  • run ตัวอย่างจบครบ มี adapter/manifest, hash ตรง และสำรองออกได้ก่อนหยุดเครื่อง.
  • ทดลอง budget alert, idle-cost check, volume cleanup และ data-retention.
  • ไม่มี data/adapter/credentials ใน Qdrant, FaroAI Docker image, Git หรือ public object storage.

10. ลำดับงานเมื่อเริ่มลงมือ

  1. เลือก Cloud/region และยืนยันราคา, quota, GPU availability ใน console.
  2. สร้าง permissions, budget alert, private access, encrypted EBS และ GPU instance.
  3. ทำ provisioning script แบบ idempotent สำหรับ mount, environment check, logs และ start/stop.
  4. ติดตั้ง dependencies, pin เวอร์ชันที่ทดสอบ, warm model cache และสร้าง AMI.
  5. ทดลอง Stop/Start ตรวจ cache persistence และค่า disk.
  6. ลองกับ approved dataset ชุดเล็ก แล้วเก็บเวลา/token count จริงเพื่อแทนค่าประมาณ.
  7. สรุป runbook, ต้นทุน, cleanup policy และผลตรวจ; อัปเดต SPEC/changelog หาก implementation ต่างจากแผน.
