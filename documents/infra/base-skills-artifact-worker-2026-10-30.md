# Artifact worker: infrastructure handoff

Status: image built and isolated renderer checks passed; worker not deployed or end-to-end verified. ADR: [0036](../adr/0036-platform-base-skills.en.md). Research date: 2026-10-30; review by 2027-01-30, or sooner on image, dependency, Docker, security advisory, network or volume changes.

- The optional `artifacts` Compose profile adds a Python 3.12 slim-bookworm worker with pinned document libraries and Noto fonts. The worker has only the internal data network for PostgreSQL and Redis, no published ports, a read-only root, a bounded `/tmp`, no capabilities and no Docker socket. Gateway receives a read-only artifact volume and supplementary group 10002. The worker uses UID/GID 10002 and needs a writable private volume. Inputs are data for fixed renderers, not code.
- Default operation keeps `FAROAI_ARTIFACT_ENABLED=false`. On 2026-10-30 the current named volume was observed to be owned by 10002:10002, writable by that worker user, and traversable by the running API. This is a point-in-time check; verify pre-existing or replacement volumes and file-level group access before enabling. Do not enable until the job migration, services and retention tests have passed.
- The planned default is 24-hour job and artifact expiry. Validate the retention choice before production release. An unavailable Redis notification does not discard a committed job; PostgreSQL remains the source of truth. Redis must not contain document content. Confirm backups and cleanup semantics for the deployment.
- The worker requires dedicated connections in `FAROAI_ARTIFACT_DATABASE_URL` and `FAROAI_ARTIFACT_REDIS_URL`; it deliberately does not fall back to the application's broad credentials. Migration `017_artifact_worker_access.sql` prepares a NOLOGIN group with limited PostgreSQL column permissions and no password. Separately provision a login and secret, grant the group to that login, audit inherited/PUBLIC privileges and RLS, and test every query/lock plus denied access in an isolated database. The worker role is service-wide across tenants, not database-enforced tenant isolation. Missing credentials prevent startup. No role or credential has yet been created in the running database.
- Redis currently has a shared unauthenticated configuration; a dedicated URL alone does not restrict access while an unrestricted default user remains. Plan separate ACL identities for every existing Redis caller and healthcheck before restricting the default, verify the worker only needs its artifact queue and necessary client setup commands, and test client compatibility and reconnection. Worker falls back to PostgreSQL polling when Redis fails, so monitor queue failures separately. Redis is not protected in transit by AUTH alone; assess TLS and network isolation. No Redis ACL or credential was changed.
- Static `docker compose --profile artifacts config --quiet` passed for the effective default, local and hosted profiles. The built image passed renderer and mocked worker security tests with no network, a read-only root and bounded tmpfs. Runtime database/Redis connectivity, forbidden egress, secrets, file-level gateway access, Thai glyph shaping/layout, recovery, expiry, memory use and output downloads remain unverified. No live business records were created.
- Nominal Compose steady-state limit including the worker is approximately 3.30 CPUs and 6400 MiB before migration/host/tmpfs overhead. Confirm actual host capacity, overlapping startup and available disk before building or enabling. Existing disk free space was approximately 2 GiB on 2026-10-30; avoid keeping obsolete project image builds or package caches. Do not prune shared images or volumes.
- DevOps handoff: build from `artifact-worker/` with Python 3.12 slim-bookworm and Noto packages; no runtime installs, no build secrets. Deploy gateway, AI service and Backoffice from their own contexts; run migration `016_skill_artifacts.sql` using the existing migration procedure. Test rollback with artifacts disabled and the worker stopped; never delete artifact or database volumes as part of rollback. Do not claim production readiness until the checks above pass.
