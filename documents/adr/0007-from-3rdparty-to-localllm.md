# ADR-0007: External-to-local model improvement

- **Status:** Superseded by [ADR-0012](0012-consented-model-improvement-and-training.md)
- **Date:** 2026-10-04
- **Deciders:** Jakapong Chan-o ( PM )

## Context

เนื่องด้วยค่า token ปัจจุนบันมีมูลค่าแพงมาก ต่อการ prompt หรือ ค้นหาข้อมูล 1 ครั้ง

## Decision
ทำให้ faroai เป็น Centralize ที่สามารถเรียนรู้ตัวเองได้ จาก prompt ที่มีการไปเชื่อมต่อกับ 3rd party อย่าง openrouter หรือ จากคำตอบที่ได้รับ

กติกาที่ทีมต้องทำตาม:

- การพัฒนา rag ของ faro ai สำหรับงาน local ต้องมีการพัฒนาที่ ครอบคลุมมากพอที่จะทำงานผ่าน model ที่ฉลาดน้อยกว่า เพราะ model ที่ ใช้ใน lmstudio 
จะฉลาดไม่เท่า  model ที่เราใช้ผ่าน openrouter 

- ทุกๆครั้งที่มีการใช้ model ภายนอก หลังจากที่มีการ prompt แล้ว faroai จะต้องมีการเก็บข้อมูลไว้ใช้สำหรับการพัฒนา rag ของตัวเอง ทั้งนี้ ลูกค้า หรือ ผู้ใช้ ai นั้นๆจะต้อง Accept หรือยอมรับว่าให้ใช้ข้อมูลที่ prompt มาในการเอาไปพัฒนาต่อเช่นกัน เพื่อไม่ให้เป็นการผิดกฏหมายด้าน privacy และ consent

- ข้อมูลที่ faroai เก็บไว้เพื่อทำการพัฒนา จะต้องแบ่งออกเป็ฯ 2 ส่วน ได้แก่
    ส่วนแรก : คือส่วนที่ faroai พัฒนาเข้า centralize เพื่อให้ลูกค้าทุกคนได้ใช้
    ส่วนที่สอง : คือส่วนที่ faroai พัฒนา แต่เก็บไว้ใช้ ภายใต้ localllm ของลูกค้าองค์กรนั้นๆเท่านั้น เนื่องด้วยความลับทางธุรกิจ

## Consequences

**ข้อดี**
- ไม่ต้องเรียก third party ตลอดเวลา และทำให้เราสามารถมี faroai ของเราฉลาดยิ่งขึ้นในอนาคตสามรรถแยกขยายได้เป็นหลาย model หลายรูปแบบการใช้งาน
